# mash-site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and deploy a single static, responsive marketing page telling the book-mash → mash-core extraction story, with a section per project, linking to both GitHub repos.

**Architecture:** Plain HTML + CSS, no framework, no build step, no JavaScript. One `index.html`, one `style.css`. Deployed as a static site via the Vercel CLI.

**Tech Stack:** HTML5, CSS3 (grid/flexbox, one media query breakpoint). Vercel CLI for deployment. Git repo matching the existing book-mash/mash-core sibling-project pattern (own repo, MIT license, pushed to GitHub).

## Global Constraints

- No JavaScript framework, no bundler, no build step — content is served as-is.
- Single mobile breakpoint at 640px; no layout requires JS to reflow.
- All project descriptions and install snippets are copied verbatim from the real READMEs (`/Users/timur_isachenko/Dev/LifeOS/book-mash/README.md`, `/Users/timur_isachenko/Dev/LifeOS/mash-core/README.md`) — no invented claims.
- MIT license, matching book-mash/mash-core's existing `LICENSE` text (`Copyright (c) 2026 Timur Isachenko`).
- No analytics/tracking, no custom domain — ships on Vercel's default `*.vercel.app` URL.
